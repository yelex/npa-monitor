# Спека: не пересоздавать сигнал по URL, отклонённому экспертом (PLAN.md Фаза 9, п.3)

Статус: **реализовано, 2026-08-24**.

## 1. Проблема (по формулировке PLAN.md/AGENTS.md раздел 16 п.15)

Из обратной связи пилота: «отклонённые экспертом ссылки (особенно типовые info-страницы
sfr.gov.ru) пересылаются повторно после отклонения». Примеры дампа: [70]/[4]/[20]/[63]/
[65]/[68].

## 2. Расследование

Проверены реальные URL всех 6 примеров (`signals_dump.txt`):

| Сигнал | URL | Причина повторного появления |
|---|---|---|
| [70]/[4]/[20] | `sfr.gov.ru/branches/<region>/info/~<дата>/<id>?info_category=N` | Дата в самом пути URL меняется день ото дня для того же статичного справочного материала — каждый обход видит «новый» URL, дедуп по точному URL (и по канонизированному, `parser/dedup.py::canonicalize_url`, п.2) его не ловит: строки физически разные. |
| [63]/[65]/[68] | `tass.ru/politika/28033329`, `tass.ru/.../28033087`, `ria.ru/20260821/er-2112308145.html` | Три **разных**, невоспроизводящихся URL — политические заметки про «народную программу ЕР», ошибочно классифицированные как релевантные (совпадение по ключевым словам ЖС/меры поддержки в другом контексте). Не случай «тот же URL пересоздан» — это отдельная проблема точности классификатора, уже отдельным пунктом чек-листа (Фаза 9 п.6). |

**Вывод:** реального случая «эксперт отклонил сигнал → тот же самый (после
канонизации) URL повторно замечен парсером → создан новый сигнал» в дампе не
обнаружено. Единственный воспроизводимый механизм повторного появления —
рансующаяся дата в пути URL (`sfr.gov.ru/branches/*/info/`), и он **уже полностью
закрыт** более ранней задачей этой же фазы:

- `parser/filters.py::is_excluded_path()` (Фаза 9, п.1, `docs/SPEC_stale_publications_filter.md`)
  исключает весь путь `sfr.gov.ru/branches/<любой>/info/` из обхода **до** дедупа и
  классификации — независимо от даты/`id`/`info_category` в пути, независимо от
  того, был ли когда-то отклонён похожий сигнал. Такие публикации никогда не создают
  сигнал заново, а значит и вопрос «помнить решение эксперта по этому паттерну»
  снимается: паттерн не доходит до сигнала вообще.
- `documents_seen` (уникальный констрейнт по `doc_url`, с 2026-08-24 —
  канонизированному, `docs/SPEC_url_canonicalization.md`) в принципе не позволяет
  повторно обработать один и тот же (канонизированный) URL, **независимо от статуса**
  ранее созданного по нему сигнала (Новый/Отклонён/Завершён и т.п.) — `register_
  document_seen` проверяет только факт «URL уже видели», не читает `Signal.status`.
  Значит структурно для любого URL, у которого строка стабильна между обходами (не
  только sfr.gov.ru), пересоздание сигнала после отклонения уже невозможно — это
  было верно и до Фазы 9, просто не было явного регрессионного теста именно на этот
  сценарий (проверялось только «дубликат публикации», не «дубликат отклонённой
  публикации»).

## 3. Решение

**Оба пункта чек-листа закрываются без нового кода**, по аналогии с Фаза 9 п.1
(«fetch_window_start уже давал это — код менять не пришлось, добавлен тест»):

- Пункт 1 («хранить решение эксперта в привязке к каноническому URL») — уже
  гарантировано архитектурой `documents_seen` + `canonicalize_url`. Статус сигнала
  (в т.ч. «Отклонён») не участвует в проверке дедупа и не должен — сам факт «URL уже
  обработан» уже достаточен, дополнительная таблица/поле для хранения именно
  «отклонён» была бы избыточной (дублировала бы уже существующий эффект). Добавлен
  явный регрессионный тест, фиксирующий это поведение (раздел 4) — до этой задачи
  оно было верным случайно, не по контракту, теста не было.
- Пункт 2 («закрыть паттерн `sfr.gov.ru/.../info/` каноническим ключом дедупа без
  даты») — **уже закрыт сильнее исходной формулировки**: вместо канонического ключа
  дедупа (что оставляло бы публикацию видимой, но дедуплицированной) весь паттерн
  полностью исключён из обхода (`is_excluded_path`, Фаза 9 п.1). Действие эксперта
  «отклонить» для таких страниц с этой задачи вообще не требуется — они не доходят
  до сигнала. Дополнительного кода не требуется, тесты уже есть
  (`tests/test_filters.py::test_is_excluded_path_matches_sfr_branches_info`,
  подтверждает независимость от даты/id/`info_category`).

## 4. Результат выполнения

- [x] Расследование дампа (раздел 2) — подтверждено, что оба пункта чек-листа уже
      фактически закрыты предыдущими задачами Фазы 9 (п.1 — исключение пути, п.2 —
      канонизация URL), нового кода не требуется.
- [x] Регрессионный тест на явный контракт «отклонённый URL не пересоздаёт сигнал»:
      `tests/test_orchestrator.py::test_process_source_does_not_recreate_signal_for_url_rejected_earlier`
      — публикация создаёт сигнал → эксперт отклоняет (`db.service.transition_status`
      → `SignalStatus.REJECTED`) → повторный обход той же (в т.ч. не канонически
      идентичной по регистру/`www.`) ссылки не создаёт второй сигнал и не меняет
      статус существующего.

      изменённом файле.
