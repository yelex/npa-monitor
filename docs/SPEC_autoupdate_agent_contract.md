# Спека: контракт передачи сигнала агенту автообновления (Этап 4/Фаза 5, AGENTS.md раздел 16 п.8)

Статус: **реализовано (2026-08-24)** — `bot/autoupdate_client.py`,
`bot/main.py::_finish_npa_flow`/`_reconcile_spool_tasks`/`_results_scan_loop`,
`config.py::autoupdate_spool_dir`/`autoupdate_mode`, тесты в `tests/test_bot_main.py`.

## 1. Контекст

`bot/autoupdate_client.py::AutoUpdateAgentClient` — заглушка: при переходе сигнала в
«Передан агенту» (`_finish_npa_flow`) вызов только логируется. Агент автообновления —
локальный проект `auto` (SO-MAS, LangGraph): не поднимается как HTTP-сервис, рабочий
артефакт — спайк `spikes/revision_react_agent` (ReAct-агент на DeepAgents + GigaChat).
Решение пользователя (2026-08-24): **стык минимальный** — npa-monitor передаёт только
`npa_url + ЖС + регион`; реестр мер, XLSX/БД, diff — внутреннее дело агента.

## 2. Проблема

Нужен контракт «задача на актуализацию», который не требует HTTP-сервиса сейчас,
не потребует переделки бота позже и даёт обратный путь: результат агента → карточка
в TG → решение аналитика (`/complete` уже есть).

## 3. Решение (с учётом ревью Клода)

### 3.1 Транспорт: файловый spool (MVP) → HTTP (позже)

Каталог-спул `AUTOUPDATE_SPOOL_DIR` (env, по умолчанию `<data>/autoupdate_spool/`):
- `tasks/<task_id>.json` — задача (бот пишет, агент забирает)
- `results/<task_id>.json` — результат (агент пишет, бот читает и архивирует)
- `results/.processed/` — архив обработанных ботом результатов

Миграция на HTTP: интерфейс не меняется, реализация `send()`/скана подменяется
по `AUTOUPDATE_MODE=spool|http`; `bot/main.py` не трогаем.

### 3.2 Порядок операций (ключевой фикс ревью)

Файл задачи пишется **до** `db.commit()` перехода в SENT_TO_AGENT. Если запись упала —
переход не коммитится, аналитик видит ошибку и может повторить (переход одноразовый,
см. `_sent_to_agent_transition`). Плюс страховка: при старте бота и раз в сутки —
сверка «SENT_TO_AGENT, но файла в spool нет» → дозапись (send() идемпотентен).

### 3.3 Контракт задачи `tasks/<task_id>.json`

```json
{
  "schema_version": 1,
  "task_id": "sig-42",
  "signal_id": 42,
  "created_at": "2026-08-24T22:19:00+02:00",
  "npa_url": "https://publication.pravo.gov.ru/document/000/...",
  "discovery_url": "https://sfr.gov.ru/...",       // fallback, если npa_url нет
  "categories": ["veterans"],                       // реальные коды db.enums SignalCategory
  "region": "moscow"                                // реальные коды db.enums Region
}
```

- `task_id = f"sig-{signal_id}"` — детерминированный, идемпотентная перезапись,
  `signal_id` дублируется отдельным полем (не парсим строку).
- `npa_url: null` допустим — тогда обязателен `discovery_url` (= `Signal.source_url`).
- Реестр мер / measure_id / diff в контракт не входят.

### 3.4 Контракт результата `results/<task_id>.json`

```json
{
  "schema_version": 1,
  "task_id": "sig-42",
  "signal_id": 42,
  "status": "done | nothing_found | error",
  "finished_at": "2026-08-25T01:40:00+02:00",
  "summary": "Найдено: изменение ежемесячной выплаты ВБД (Закон №47)",
  "details": "..."
}
```

### 3.5 Атомарность и идемпотентность

- Обе стороны пишут через tmp-файл + `os.rename` (атомарно на одной ФС).
- **Идемпотентность результатов — на стороне бота (потребителя)**: после отправки
  карточки бот перемещает файл в `results/.processed/`. При перезапуске между
  отправкой и перемещением дубликат возможен — принимаем (карточка дублируется, но
  переход статуса одноразовый, вреда нет). Дополнительно бот игнорирует файлы с
  неизвестным `signal_id` (логирует).

### 3.6 Обратная связь в TG

- Отдельный asyncio-луп `_results_scan_loop`, интервал 5 мин (не `_digest_loop`,
  тот спит до утренней сводки). Сканирует `results/*.json`, шлёт карточку
  «Агент завершил задачу по сигналу N: summary (+details)», архивирует.
- Решение за аналитиком: `/complete <id>` (уже есть). Новых статусов не вводим.

### 3.7 Сигнатура клиента

`AutoUpdateAgentClient.send(signal: Signal, npa_url: str | None, discovery_url: str,
categories: list[str], region: str) -> Path` — spool-реализация пишет задачу и
возвращает путь (для логов/тестов). Заглушка `measure_id` уходит.

## 4. Проверка

- Юнит: запись задачи до коммита (фейл записи → нет коммита); контракт-поля из
  реальных enum; атомарная запись; идемпотентный повторный send.
- Интеграционный тест: фикса `results/sig-42.json` → бот шлёт карточку и архивирует;
  повторный скан — тишина.
- Ручной: /digest → ✅ → ссылка → подтверждение ЖС/региона → в спуле `tasks/sig-N.json`.

## 5. НЕ входит

- HTTP-реализация транспорта (только `AUTOUPDATE_MODE` в конфиге).
- Сторона агента (auto): забор задач/запись результатов — отдельная задача.
- Автопереход статусов по результату агента.
