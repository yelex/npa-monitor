## Контекст
`scan_autoupdate_results()` (bot/main.py, SPEC автoupdate 3.6) шлёт аналитику карточку через
`bot.send_message(uid, text)`. Details у реальных результатов бывают большими (sig-143 — 11 КБ).

## Проблема
Telegram-лимит 4096 символов на сообщение. При превышении `send_message` кидает
`TelegramBadRequest: message is too long`, исключение вылетает из `scan_autoupdate_results`,
файл не архивируется → скан-луп падает на нём каждые 5 минут и блокирует отправку всех
последующих результатов (инцидент 27.08: sig-143 заблокировал sig-155 и 4 старых).

## Предполагаемый фикс
1. В `result_card()` оставить сборку как есть (одна логическая карточка).
2. Перед отправкой в `scan_autoupdate_results()`: если текст > 3900 символов (запас на разметку),
   резать на части ≤3900 по границам строк (последний кусок может быть коротким) и слать
   последовательными `send_message`. Первый кусок — как сейчас; в конец первого не добавлять
   «(1/2)» — вместо этого префикс «(1/N)», «(2/N)» … в начале 2-го и далее, либо проще:
   помечать каждый кусок «(i/N)» кроме случая N=1.
3. Отправка каждому uid: если один из кусков упал — логировать и продолжать (не ронять луп),
   но НЕ архивировать файл, чтобы карточка попыталась отправиться снова? Нет: повторная
   отправка приведёт к дублям у uid, которым дошло. Решение: архивировать всё равно
   (результат виден в .processed), ошибку отправки — в лог + текст ошибки уже не блокирует
   очередь. Компромисс принят: доставка хотя бы первому адресату > гарантия отсутствия дублей.
4. Без изменений схемы БД, без новых зависимостей.

## Как воспроизвести
1. Положить в spool `results/sig-test.json` с details 11 КБ.
2. Дождаться скана (≤5 мин) → до фикса: циклический `results scan loop error`; после: 3
   сообщения (1/3, 2/3, 3/3), файл в `.processed/`.

## Критерии
- [ ] sig-143 (11 КБ) доставляется без ошибок лупа, файл архивируется.
- [ ] sig-155 и старые доставлены после разбора очереди.
- [ ] Луп не падает на ошибках отправки одному из uid.
- [ ] Тест на резку: куски ≤3900, режем по `\n`, не рвём HTML-теги (details — plain text,
      экранирован, тегов внутри нет).
