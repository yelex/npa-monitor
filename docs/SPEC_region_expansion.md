Статус: **реализовано и проверено (2026-08-25, коммит `81381f4`)**.

## Итоги

- Тесты: **338/338 ✅** (независимый прогон).
- Ревью Claude против спеки: **вердикт OK**, критичных нет. Проверено: blast radius
  полный (остатков `Region`-enum нет), слаги 87 регионов без коллизий и дублей с
  rf/moscow/undefined, лемма-матчинг — подмножество лемм с фильтром предлогов,

- Некритичное (вне рамок спеки): `load_regions()` не кэшируется — перечитывает

## Контекст

MVP-периметр регионов (rf/moscow/undefined) упирается в два ограничения:
1. Аналитик в боте не может выбрать регион меры вне enum — а база мер
   (`data/benefits_knowledge_base.json`) покрывает 89 регионов, и аналитик
   буквально видит волгоградскую меру, которую не может привязать к Волгограду.
2. Расширение требует правок в двух местах (enum + yaml), `catalog.load_regions()`
   падает `CatalogError`, если code из yaml не член `db.enums.Region`.

Дизайн согласован с Claude 2026-08-25 (см. историю сессии).

## Решение

### 1. Signal.region: enum → строка-код

- `Signal.region`: `Mapped[Region]` (`Enum(Region, native_enum=False, length=16)`) →
  `Mapped[str]` (`String(64)`), значение — `RegionEntry.code` из `regions.yaml`.
- `db.enums.Region` удаляется; вместо него строковые константы-сентинелы
  `REGION_RF="rf"` / `REGION_MOSCOW="moscow"` / `REGION_UNDEFINED="undefined"`
  (RF/undefined участвуют в логике отдельными ветками).
- Валидация: `code in {r.code for r in load_regions()}` в рантайме при вводе
  (по аналогии с проверкой SignalCategory в `catalog.py`, не at-import-time).
- **Миграция не нужна**: у Enum-колонок проекта нет CHECK-констрейнта
  (`create_constraint` не передан, дефолт False), реальная DDL — `VARCHAR(16)`,
  SQLite длину не enforce'ит. Изменение метаданных SQLAlchemy чисто ORM-level,
  существующие байты (`rf`/`moscow`/`undefined`) валидны без DDL-операций.

**Blast radius (все места, типизированные `Region` — править все):**
- `db/catalog.py`: убрать `RegionEntry.region: Region` (код — единственный
  идентификатор), `load_regions()` перестаёт валидировать code против enum
  (именно это сейчас падает `CatalogError` на новых регионах).
- `parser/classifier.py`: `detect_region()`/`detect_priority()` — строки +
  сентинел-константы.
- `parser/llm_priority.py`: датакласс `region: Region` → `str`.
- `db/service.py`: `create_signal(..., region: str = REGION_UNDEFINED, ...)`.
- `bot/main.py`: ~8 точек (`Region(code)`, `.value`, сигнатуры
  `_finish_npa_flow`/`_advance_to_signal_type`/`_audit_reason`).
- ~9 тестовых файлов, использующих `Region` — обновить вместе с кодом.

### 2. regions.yaml: все ~89 сразу, генерацией

- Полный справочник генерируется скриптом из уникальных значений `region` базы
  мер (`scripts/gen_regions_yaml.py`), не вручную.
- **`rf`/`moscow`/`undefined` — существующие записи yaml закреплены руками;
  генератор их НЕ создаёт и НЕ перезаписывает** (иначе «Москва» транслитерируется
  в `moskva` и существующие `signals.region='moscow'` молча потеряют
  соответствие). `undefined` в базе мер отсутствует — остаётся только в yaml.
- `code` — слаг имени (kebab-case, «Волгоградская область» →
  `volgogradskaya-oblast`); скобки/тире/Ё-Й-Х-Щ — по транслитерации; в генераторе
  обязателен `assert` на уникальность кодов (коллизий на текущих 89 нет,
  проверено, но будущие обновления базы должны ловиться).
- `sources: []` для всех, кроме РФ (федеральные в `sources.yaml`) и Москвы —
  штатно, парсер туда не ходит; основной канал обнаружения — Yandex Search.
- Падежные формы в yaml НЕ хранить — вычисляются матчингом (п.3).

### 3. Матчинг ввода аналитика

- Ступень 1 (быстрый путь): текущий casefold-substring по `name`/`code` — как есть.
- Ступень 2 (при 0 совпадений): лемматизация запроса и токенов `name` через
  pymorphy3 (`_lemma`-паттерн из `db/measures.py`), сравнение по пересечению
  множеств лемм. Покрывает «Татарстане», «в Волгоградской области».
- `find_region_matches` возвращает `RegionEntry`; логика «1 матч — принять,
  0 — не найден, 2+ — список кандидатов» не меняется.

### 4. Единый источник правды имён

- Убрать захардкоженный `_REGION_NAME` в `db/measures.py` — `_matches_region`
  берёт имя региона через `catalog.load_regions()` по коду сигнала.
  **Исключение:** `undefined` — отдельный спецкейс «без фильтра» (в базе мер
  такого региона нет), остаётся веткой `wanted is None → True`.
- Guard-тест: каждое уникальное `region` из снапшота базы мер должно иметь запись
  в `regions.yaml` (по образцу существующей проверки code↔enum в `catalog.py`).
  Ловит рассинхрон при обновлении базы.

### 5. Бот

- Кнопки РФ/Москва/«Не определён» остаются (быстрый путь), «Другое» → текстовый
  ввод с новым матчингом.
- В карточке сигнала/задаче агенту регион отображается именем из справочника.
