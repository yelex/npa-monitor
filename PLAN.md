# План реализации

Источник требований и всех архитектурных решений — [AGENTS.md](AGENTS.md).
Этот файл — исполняемый чек-лист задач для итеративной (в т.ч. автономной,
через `ralph.sh`) реализации. Каждая задача должна быть выполнима за одну
итерацию: код + (где применимо) тесты + коммит.

Правила работы с этим файлом (важно для ralph-цикла):
- Задачи выполняются **сверху вниз**, по одной за итерацию, в рамках текущей
  фазы — фазы не пропускаются и не распараллеливаются.
- Выполненная задача помечается `[x]`. Если задача заблокирована (нет
  доступа/кредов/контракта) — оставить `[ ]` и дописать
  `<!-- BLOCKED: причина -->` рядом, перейти к следующей незаблокированной
  задаче.
- Любое отклонение от AGENTS.md (найдена неточность, нужно уточнение) —
  фиксировать в разделе «Открытые вопросы» AGENTS.md, не изобретать
  требования на ходу.
- Каждая завершённая задача — отдельный git-коммит с понятным сообщением.

## Фаза 0 — Скелет проекта

- [ ] Инициализировать git-репозиторий (если ещё не инициализирован),
      добавить `.gitignore` (venv, `__pycache__`, `*.db`, `.env`).
- [ ] Создать структуру пакетов: `parser/`, `bot/`, `storage/`, `common/`,
      `data/` (справочники ЖС/регионов), `tests/`.
- [ ] Настроить `pyproject.toml`/`requirements.txt`, менеджер зависимостей,
      базовый `README.md` с инструкцией запуска для разработчика.
- [ ] Настроить `.env.example` (переменные: `TELEGRAM_BOT_TOKEN`,
      `ALLOWED_TELEGRAM_USER_IDS`, `GLM_API_KEY`, `GLM_API_URL`,
      `AUTOUPDATE_AGENT_*` — заглушки, реальные значения не коммитить).
- [ ] Настроить базовый CI-шаг (хотя бы `pytest` + линтер) — можно локальный
      Makefile/скрипт, если нет CI-платформы.

## Фаза 1 — Справочники (данные, не код)

- [ ] Спроектировать формат справочника ЖС (`data/life_situations.yaml` или
      аналог): id, название, ключевые слова (раздел 5.1 AGENTS.md). Загрузить
      туда 3 стартовые ЖС.
- [ ] Спроектировать формат справочника регионов
      (`data/regions.yaml`/таблица в SQLite): код субъекта, название, домены
      источников (портал правительства, соцзащита, портал правовой
      информации, сайт главы региона).
- [ ] Написать одноразовый скрипт-краулер `scripts/build_region_sources.py`,
      который собирает ссылки с `http://pravo.gov.ru/links/region/` и
      заполняет черновик справочника регионов (89 субъектов). Ручная
      верификация результата — отдельным шагом, не блокирует код.
- [ ] Написать загрузчик справочников в SQLite при старте приложения, с
      проверкой, что добавление новой ЖС/региона не требует правок кода
      (тест: добавить тестовую ЖС в файл справочника, убедиться, что парсер
      её подхватывает).
- [ ] Сформировать белый список доменов источников (федеральные + иные из
      раздела 3 AGENTS.md + собранные региональные) как часть справочника.

## Фаза 3 — Парсер: сбор публикаций

- [ ] Общий HTTP-клиент с ретраями (3 попытки, затем пропуск источника до
      следующего цикла — раздел 9 AGENTS.md), таймаутами, User-Agent.
- [ ] Адаптер для федеральных источников (5 URL раздела 3 AGENTS.md) —
      получение списка публикаций за окно времени (24ч ежедневно / 7 дней

- [ ] Адаптер для «иных» источников (СМИ/обзорники, раздел 3 AGENTS.md).
- [ ] Адаптер для региональных источников — параметризованный доменом/URL из
      справочника регионов (не хардкод конкретных регионов в коде).
- [ ] Фильтр по типу контента: только текстовые публикации (раздел 4.6).
- [ ] Проверка домена публикации по белому списку перед дальнейшей
      обработкой (требование безопасности, раздел 10).

- [ ] Адаптер к GLM (интерфейс `ClassifierClient` с одной реализацией

- [ ] Тесты классификации на синтетических примерах публикаций (по каждой

## Фаза 9 — Проверка критериев готовности

Сверка с разделом 11 AGENTS.md — каждый пункт закрывается тестом или
ручным сценарием:

- [ ] Парсер обходит источники по расписанию и создаёт сигналы.
- [ ] Бот присылает сводку в заданное время.
- [ ] Эксперт может взять в работу / отклонить / отложить сигнал.
- [ ] Бот принимает и проверяет ссылку на НПА.
- [ ] Бот передаёт ссылку агенту (через адаптер, даже если адаптер — пока
      заглушка).
- [ ] Добавление новой ЖС и нового региона проверено end-to-end через
      справочник, без изменений кода.
- [ ] `/today /pending /history /stats` работают на реальных данных.
- [ ] Все граничные случаи раздела 9 AGENTS.md покрыты тестами или ручной
      проверкой.
