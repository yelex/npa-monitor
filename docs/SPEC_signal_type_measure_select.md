## Контекст

Коннектор npa-somas (спека v3, коммит 1f13331) ждёт задачу `schema_version: 2`:
`signal_type: "change"|"new"`, `measure_id`, `measure_row_hash`. Снапшот базы —
`data/benefits_knowledge_base.json` (2297 записей; файл-перезаливка одновременно
с копией в npa-somas — инвариант). Поля: `measure_id`, `measure_name`,
`human_readable_name`, `region`, `source_dataset`, `origin_sheet`, `tags`,
`search_corpus_lemmatized`, `row_hash`.

FSM сейчас: сигнал → ✅ → ссылка → ЖС → регион → `_finish_npa_flow`.

## Решение

### 1. Два новых FSM-шага (после региона)

- **Тип сигнала**: кнопки «Изменение существующей меры» / «Новая мера» →
  `signal_type`. Для new шаг выбора меры пропускается.
- **Выбор меры** (change): саджест кнопками + ручной ввод (см. п.2).
- `_finish_npa_flow` вызывается теперь из конца второго шага (точка вызова
  переносится из `on_region_button`/`on_region_manual`).

### 2. Саджест: гибрид косинус + подстрока

Пул = записи базы с непустым `measure_id` (799 записей с null ИСКЛЮЧАЮТСЯ —
выбор такой записи неотличим от «нет в базе»), отфильтрованные по:
- **ЖС**: по `source_dataset`+`tags`, НЕ по префиксу origin_sheet (СБЕР_СВО,
  СБЕР_инвалидам, Лист1 префиксами не покрываются): veterans→ВБД-датасеты,
  disabled→инвалидные, svo→СВО (маппинг уточнить по фактическим значениям
  source_dataset при реализации);
- **регион**: moscow→«Москва», rf→«РФ», undefined→все.

Скор = 0.6*cos + 0.4*подстрока (в measure_name/human_readable_name), тюнинг по
живым сессиям. Косинус — руками на Counter-BoW (numpy/sklearn НЕ тянуть).
Лемматизация запроса: **pymorphy3** (лёгкая, чистый python) — корпус лемматизирован
полным морфоанализатором, суффиксный стеммер `parser/ru_stem.py` даст расхождение
нормализации и просадит recall. pymorphy3 — новая зависимость.

Экран: топ-8 + кнопки «Ещё 8» / «Вписать вручную» (текст → тот же скор → топ-8) /
«Нет в базе» (measure_id=null, honest). Список кандидатов/запрос/офсет — в FSM
state; callback_data только `msel:{sig_id}:{page|idx}` (лимит 64 байта).

### 3. Задача v2 и старые данные

- `_finish_npa_flow` пишет schema_version=2 + signal_type + measure_id +
  measure_row_hash (row_hash записи на момент выбора; new/нет в базе → null).
- **Signal.signal_type, Signal.measure_row_hash** — новые колонки через
  `db/session.py::_ensure_columns` (идемпотентный ALTER TABLE; Alembic в проекте
  НЕ используется). `Signal.measure_id` УЖЕ есть (models.py:67) — не добавлять.
- Старые SENT_TO_AGENT без подтверждённого типа: сверка при старте (`_reconcile_
  spool_tasks`) дорабатывается — проверяет schema_version внутри существующего
  файла и перезаписывает v1→v2 (сейчас проверяет только наличие файла — 4 v1-задачи
  так и остались бы v1). Для старых сигналов без данных пишет
  `signal_type:"change", measure_id:null` с пометкой в comment — осознанная
  деградация: тип не восстанавливаем, ветка «мера не выбрана» отработает дифф
  по кандидату от коннектора; при необходимости аналитик перенаправит вручную.

## Проверка

- Юнит: фильтр пула (source_dataset+tags, исключение measure_id=null, регион),
  гибридный скор (косинус pymorphy3 vs корпус, подстрока-буст, пагинация),
  FSM обе ветки (переписать ~29 тестов, зашитых на «регион → сразу SENT_TO_AGENT»),
  задача v2 все поля, v1→v2 перезапись сверки, _ensure_columns.
- Ручной: /digest → ✅ → ссылка → ЖС → регион → «изменение» → «выплата за
  контракт» → выбор → в спуле tasks/sig-N.json со schema_version=2.
