# SPEC: weekend zero-signal false alert

## Статус
proposed

## Контекст
- Парсер ходит по cron `0 6 * * 1-5` (пн-пт, 06:00 Amsterdam).
- `_digest_loop` бота шлёт сводку каждый день 08:00 локального времени, без учёта выходных.
- `check_zero_signal_degradation` (bot/health_alerts.py) проверяет фиксированное окно «последние 24 часа»: нет сигналов И нет успешных обходов ЖС-значимых источников.

## Проблема
Инцидент 05.09 (суббота): в 08:00 сб последний прогон парсера (пт 06:00) был ~26ч назад — вывалился за окно 24ч. Оба условия «деградации» выполнились → эксперту ушёл ложный алерт «проверьте прокси/ключи», хотя пятничный прогон был успешным (11/12 источников ok, Yandex ok, 23 новых сигнала). Аналогично сработало бы в понедельник до прогона.

## Предполагаемый фикс
Окно проверки — не «24 часа», а «с последнего планового запуска парсера»: самый недавний 06:00 локального времени в пн-пт (≤ now). В сб/вс и пн-до-прогона окно накрывает пятничный успешный прогон → ложного алерта нет. Реальная деградация (прогон был, но всё упало) ловится как раньше.

Отдельно: сводку («📬» / «Новых сигналов нет») в сб/вс не слать — данных за выходные всё равно нет.

## Как воспроизвести
- Было: в сб 08:00 local `check_zero_signal_degradation` → True (последний success 26ч назад) → алерт.
- Стало: окно от пт 06:00 → success пт внутри окна → False.
