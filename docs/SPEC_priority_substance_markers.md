# Спека: приоритизация не должна занижать явные «новая мера» без маркера документа
(PLAN.md Фаза 9, п.5)

См. также итог раздела 2 — вместо нового списка фраз решение свелось к фиксу
стемминга слова «новый» + расширению гейта `detect_priority` на `priority_high_words`.

Статус: **реализовано, 2026-08-24**.

## 1. Проблема

`parser/classifier.py::detect_priority` сейчас безусловно возвращает `Priority.LOW`,
если в тексте нет ни одного маркера документа (5.3: «постановление», «указ», «закон»,
«приказ», «распоряжение») — независимо от того, насколько явно текст описывает
конкретное новое/изменённое событие меры поддержки:

```python
def detect_priority(text, keywords, region):
    text_lower = text.lower()
    if not _contains_any(text_lower, keywords.document_markers):
        return Priority.LOW           # <-- безусловный ранний выход
    if region == Region.UNDEFINED:
        return Priority.MEDIUM
    if _contains_any(text_lower, keywords.priority_high_words):
        return Priority.HIGH
    return Priority.MEDIUM
```

Пример из дампа — сигнал [30]: «Евгений Солнцев: В Оренбуржье ввели новую меру
поддержки для [семей СВО]» (`rg.ru`, RSS). Текст явно описывает введение новой меры
(«ввели новую меру поддержки»), но не содержит ни одного слова из 5.3 (нет
«постановление»/«указ»/…) — заголовок агрегатора не цитирует конкретный документ,
хотя по сути это как раз «новый / изменение» (раздел 7 AGENTS.md, слова высокого
приоритета — `новый` там уже есть). Из-за раннего выхода `priority_high_words`
вообще не проверяется, и публикация получает `low`, хотя эксперт, скорее всего, счёл
бы её как минимум заслуживающей внимания (в дампе взята в работу, не отклонена сразу).

Второй пример из PLAN.md — [75] («Горячие документы. Луганская Народная Республика»,
`garant.ru/hotlaw/lnr/`) — рассмотрен отдельно (раздел 3): это категорийная страница-
листинг, а не публикация о конкретном событии, `low` для неё — ожидаемо корректное
поведение, не баг.

## 2. Решение

**Расследование конкретного примера [30] нашло вторую, более фундаментальную причину**,
из-за которой предложенный в PLAN.md список фраз-примеров («новая мера поддержки»
буквально) не сработал бы: `priority_high_words` уже содержит слово `новый` (AGENTS.md
раздел 7), но эвристика стемминга (`parser/ru_stem.py::_word_stem`) обрезает только 1
букву у 5-буквенных слов — `новый` → стем `новы` (4 буквы). У текста [30] форма слова —
«новУю» (винительный падеж), не «новЫй»/«новЫе» — 4-я буква после общего корня «нов»
у этих словоформ разная (`ы` в именительном, `у` в винительном и т.д.), а не
только хвост, поэтому даже проверка `_contains_any(text, ("новый",))` **уже была
сломана** для этой самой частой формы прилагательного «новый» — независимо от текущей
задачи, до неё это просто было не замечено, потому что `новый` раньше проверялся только
*после* прохода гейта по маркеру документа (см. ниже), то есть на HIGH-кейсах, где рядом
почти всегда стоит и маркер документа литературным текстом («…постановление… новое…»,
где «новое» — средний род, стем «ново» — тоже не матчится на «новую», но по факту
тестовые фикстуры проекта используют именно словарную форму `новый`, поэтому баг был
невидим).

Проверено `python3 -c`: `contains_keyword("...новую меру поддержки", ("новый",))` →
`False` до фикса.

Это меняет решение относительно черновика раздела 1 (закрытый список многословных фраз,
как предполагало PLAN.md): вместо него —

1. **Точечный фикс стемминга** для `новый` — тот же приём, что уже применён для
   `отмена` (`parser/ru_stem.py::_STEM_LENGTH_OVERRIDES`, AGENTS.md раздел 16 п.13):
   обрезать 2 буквы вместо 1 (`новый` → `нов`, инвариантный корень для всех
   падежей/родов/чисел: новый/новая/новое/новые/нового/новую/новых/новым…). Проверено —
   единственное использование `новый` в `data/keywords.yaml` — именно
   `priority_high_words`, других списков это не затрагивает, коллизии с несвязанным по
   смыслу словом (как «доброволец»/«добровольный», «отмена»/«отметил») не найдено:
   3-буквенный корень `нов` специфичен для семьи слов «новый/новость/новшество» — все
   по смыслу связаны с «новизной», ложных срабатываний не ожидается.
2. **Гейт `detect_priority`** — вместо `if not document_markers: return LOW`
   (единственное условие «не низкий»), гейт становится **ИЛИ**: маркер документа (5.3)
   **или** слово `priority_high_words` (в т.ч. починенное «новый») — то есть тот же
   список слов, что уже использовался для перехода MEDIUM→HIGH, теперь дополнительно
   защищает от ложного LOW. Отдельный новый список фраз (`priority_substance_markers`)
   не создаётся — он был бы у́же и слабее уже существующего `priority_high_words`
   (закрытый список конкретных фраз «новая мера/льгота/выплата» не поймал бы «новая
   программа»/«новое правило» и т.п., хотя логика AGENTS.md раздела 7 не привязывает
   правило именно к синонимам меры — только к словам новизны/изменения из этого же
   раздела). Условие HIGH не меняется — по-прежнему требует **обоих** списков сразу
   (раздел 7: «прямое указание на ЖС + слова «новый/…» + есть ссылка на документ»),
   меняется только порог, ниже которого приоритет не может упасть до LOW:

```python
def detect_priority(text: str, keywords: ClassificationKeywords, region: Region) -> Priority:
    text_lower = text.lower()
    has_document_marker = _contains_any(text_lower, keywords.document_markers)
    has_priority_word = _contains_any(text_lower, keywords.priority_high_words)
    if not has_document_marker and not has_priority_word:
        return Priority.LOW
    if region == Region.UNDEFINED:
        return Priority.MEDIUM
    if has_document_marker and has_priority_word:
        return Priority.HIGH
    return Priority.MEDIUM
```

Для [30] конкретно: регион у `rg.ru` не определяется (RSS-источник не входит ни в
`data/regions.yaml`, ни в федеральный список) → `Region.UNDEFINED` → итог `MEDIUM`, не
`HIGH` — это ожидаемо и правильно по уже существующему правилу «регион не определён —
принудительно средний» (раздел 4.1 AGENTS.md), не входит в объём этой задачи; главное —
`LOW` больше не проставляется вслепую только из-за отсутствия маркера документа.

## 3. Что не делает эта задача

- Не трогает [75] (`garant.ru/hotlaw/lnr/`) — категорийная страница-листинг без
  конкретной меры в заголовке, ни маркер документа, ни `priority_high_words` её не
  заденут (и не должны — она действительно не описывает конкретное событие).
  AGENTS.md раздел 7 уже явно допускает это: «низкий — аналитика, обзор... без
  указания на конкретный документ» — сама формулировка PLAN.md подтверждает, что это
  не баг («приоритет не блокирует передачу» — эксперт всё равно смог передать сигнал
  агенту вручную).
- Не меняет `detect_event_type` — текст [30] по-прежнему классифицируется как
  `event=review` (нет маркера конкретного типа события 5.4), это отдельный,
  документированный участок логики (докстринг `classifier.py`), не входит в
  периметр «приоритизация».
- Не заводит новый список ключевых слов (`priority_substance_markers`) — черновик
  раздела 1/PLAN.md предполагал его, но расследование (раздел 2) показало, что нужный
  эффект достигается точечным фиксом уже существующего `priority_high_words`/`новый`,
  без дублирующей параллельной инфраструктуры.
- Не трогает `_EXACT_WORD_OVERRIDES` и другие записи `_STEM_LENGTH_OVERRIDES`
  (`parser/ru_stem.py`) — добавляется только одна новая запись (`новый`), остальной
  механизм не меняется.

## 4. Результат выполнения

Реализовано по пересмотренному решению раздела 2 (отличается от черновика PLAN.md —
не новый список фраз, а точечный фикс стемминга + расширение гейта, см. обоснование
там же). Отклонение зафиксировано в PLAN.md рядом с чек-листом.

- **`parser/ru_stem.py`** — `_STEM_LENGTH_OVERRIDES["новый"] = 2` (стем «нов»);
  докстринг модуля дополнен разделом про находку (симметрично уже существующим
  находкам «доброволец»/«отмена»).
- **`parser/classifier.py::detect_priority`** — гейт `not (document_markers or
  priority_high_words) → LOW`; `HIGH` по-прежнему требует обоих сразу. Докстринг
  модуля (раздел «Приоритизация») обновлён.
- **Тесты:**
  - `tests/test_ru_stem.py::test_novyi_matches_declined_forms` — «новую»/«новое»/
    «новые»/«новый» все матчатся на ключевое слово `новый`.
  - `tests/test_classifier.py::test_medium_priority_from_priority_word_without_document_marker`
    — прямая регрессия на текст сигнала [30] (регион не определён → `medium`, не
    `low`).
  - `tests/test_classifier.py::test_medium_priority_from_priority_word_without_document_marker_when_region_known`
    — тот же случай с известным регионом: `medium`, не `high` (HIGH по-прежнему
    требует маркер документа тоже).
- **Итог:** `pytest -q` — 243/243 зелёных (было 240, +3). `ruff check .` — чисто на
  изменённых файлах. Проверено вживую на точном тексте [30]
  («…ввели новую меру поддержки для семей участников СВО…») — `priority` стало
  `medium` (было `low`), `region` осталось `undefined` (без изменений, как и
  ожидалось).

### Изменённые файлы

- `parser/ru_stem.py` — `_STEM_LENGTH_OVERRIDES` + докстринг.
- `parser/classifier.py` — `detect_priority` + докстринг модуля.
- `tests/test_ru_stem.py`, `tests/test_classifier.py`.
