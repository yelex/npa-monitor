    Требования к мониторингу изменений в НПА

    1.Цель

    Автоматизировать ежедневный мониторинг публикаций о принятии, изменении или отмене нормативных документов по жизненным ситуациям (ЖС) и обеспечить передачу релевантных НПА на извлечение данных после ручной верификации экспертом.

    2. Жизненные ситуации

    Система запускается с тремя жизненными ситуациями:

    1. Ветераны боевых действий.

    2. Люди с инвалидностью.

    3. Участники СВО и члены их семей.

    2.1. Требование к расширяемости

    Перечень ЖС не является фиксированным. Добавление новой ЖС не должно требовать изменения кода системы

    3. Роли

    Участник

    Функция

    Парсер

    Ежедневно в 06.00 обходит источники, находит публикации, формирует сигналы

    Бот

    Эксперт

    Изучает сигналы, отбирает релевантные, отправляет ссылку на НПА

    Агент автообновления

    Принимает ссылку на НПА, извлекает меры и параметры, возвращает структуру

    5. Ограничения для поиска

    5.1. Ограничение по географии

    Парсер ищет публикации:

    • федерального уровня — действуют на всей территории РФ;

    • регионального уровня — любого субъекта РФ.

    Для каждого сигнала система должна определять регион, к которому относится мера. Для этого:

    • используется справочник регионов РФ (89 субъектов);

    • регион определяется по источнику публикации (домен правительства региона);

    • регион может быть уточнён по тексту публикации;

    • если публикация федеральная, регион не указывается или указывается «РФ»;

    • если регион не удалось определить, сигнал помечается как «регион не определён» и имеет средний приоритет.

    5.2. Ограничение по типу документа

    Релевантными считаются публикации, которые прямо или косвенно указывают на:

    • федеральный закон;

    • указ Президента РФ;

    • постановление Правительства РФ;

    • приказ федерального министерства;

    • закон субъекта РФ;

    • указ или постановление главы региона;

    • постановление правительства региона;

    • приказ регионального министерства или департамента.

    Публикации без привязки к нормативному документу считаются нерелевантными.

    5.3. Ограничение по типу события

    Парсер ищет публикации о:

    • принятии нового документа;

    • внесении изменений в действующий;

    • отмене или утрате силы;

    • вступлении в силу ранее принятого документа;

    • изменении параметров мер: размер, сроки, условия, порядок.

    Общие аналитические обзоры без указания на конкретный документ попадают в сигналы с низким приоритетом.

    5.4. Ограничение по тематике

    Публикация релевантна, если одновременно:

    • содержит ключевые слова одной из ЖС;

    • содержит слова из тематического блока мер поддержки

    5.5. Ограничение по дате

    Парсер обрабатывает публикации:

    • за последние 24 часа при ежедневном запуске;

    • за последние 7 календарных дней при первом запуске.

    5.6. Ограничение по типу контента

    Только текстовые публикации: новости, анонсы, карточки документов. Видео, подкасты, инфографика без текстового описания не обрабатываются.

    6. Фильтрация по ключевым словам

    6.1. Ключевые слова по ЖС:

    • Ветераны боевых действий: ветеран боевых действий, ВБД, ветеран СВО

    • Люди с инвалидностью: инвалид, ребёнок-инвалид, лицо с ограниченными возможностями, инвалид с детства, инвалид по зрению

    • Участники СВО: участник СВО, мобилизованный, контрактник, доброволец, члены семей участников СВО, дети участников СВО.

    6.2. Тематический блок мер поддержки: мера поддержки, выплата, льгота, пособие, компенсация, субсидии

    6.3. Маркеры документа:

    • «постановление», «указ», «закон», «приказ», «распоряжение»;

    • «принят», «утверждён», «подписан», «вступил в силу», «внесены изменения».

    7. Формирование сигнала

    Для каждой релевантной публикации создаётся сигнал:

    • ID

    • категория (одна или несколько ЖС)

    • тип события: новый документ / изменение / отмена / вступление в силу / обзор

    • приоритет: высокий / средний / низкий

    • название документа (если извлечено)

    • реквизиты (если извлечены)

    • регион действия: «РФ» / конкретный субъект РФ / «Не определён»

    • ссылка на публикацию

    • дата и время создания

    • статус: новый / в работе / отложен / отклонён /передан агенту

    9. Сценарий Happy Path

    1. В 06:00 парсер обходит источники.

    2. В 08.00 бот присылает эксперту сводку.

    3. Эксперт открывает сигнал и нажимает ✅ Взять в работу.

    4. Бот просит ссылку на НПА.

    5. Эксперт отправляет ссылку.

    6. Бот проверяет ссылку и передаёт агенту автообновления

    10. Граничные случаи

    Парсинг

    • Источник недоступен — 3 попытки, затем пропуск до следующего цикла.

    • Нет новых публикаций — бот отправляет «Новых сигналов нет».

    • Публикация уже обработана — дубликат не создаётся.

    Ссылка на НПА

    • Ссылка недоступна — бот просит проверить.

    Эксперт

    • Сигнал более 3 дней в «В работе» — бот присылает напоминание.

    • Эксперт отклонил сигнал — сигнал помечается и не возвращается.

    • Эксперт нажал «Позже» — сигнал появится в следующей сводке.

    11. Безопасность

    • Бот работает только с ID допущенных пользователей

    • Сообщения от посторонних игнорируются

    • Все действия логируются

    • Передаваемые ссылки проверяются на допустимые домены

    12. Критерии готовности

    Система готова, если:

    • парсер ежедневно в 09:00 обходит федеральные, региональные и сигнальные источники;

    • бот в ???? присылает сводку;

    • эксперт может взять сигнал в работу, отклонить или отложить;

    • бот принимает и проверяет ссылку на НПА;

    • бот передаёт ссылку агенту;

    • добавление новой ЖС и нового региона выполняется через справочник без изменения кода;

    • работают команды /today, /pending, /history, /stats;

    • обрабатываются все описанные граничные случаи.
