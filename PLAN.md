# План реализации

Источник требований и всех архитектурных решений — [AGENTS.md](AGENTS.md).
Архитектура и оценки ниже унаследованы из `yelex/npa-monitor` (см. `git remote -v`) и
дополнены чек-листом, исполняемым автономным циклом `ralph.sh` (см. правила в конце
файла).

## 1. Архитектура

Три независимых процесса + общая БД:
- **parser/** — cron/systemd timer, ежедневный batch-job: `sources/` (адаптеры под
  источники), `fetcher.py` (httpx+tenacity, retry), `classifier.py` (ключевые слова →
  категория/приоритет), `dedup.py`, `state.py` (доверстывание пропусков).
- **bot/** — aiogram 3 (async, встроенный FSM для многошаговых сценариев: запрос ссылки
  на НПА, причины отклонения), long-running polling-процесс, не вебхук.
- **db/** — SQLAlchemy 2.0 + Alembic, общий слой для parser и bot.

Parser и bot — разные процессы (не один монолит), чтобы падение одного не роняло
другой; связывает их только БД. PDF: PyMuPDF/pdfplumber + pytesseract как fallback.
Docker Compose на VPS.

## 2. БД: SQLite для MVP

Один эксперт, обход раз в сутки, десятки сигналов/день — SQLite в WAL-режиме
достаточен, бэкап = `cp` файла, нет отдельного сервиса БД на VPS. Переход на Postgres
через SQLAlchemy почти бесшовен (расширение на 89 регионов, несколько экспертов,
полнотекстовый поиск).

Таблицы:
- `signals` — карточка сигнала (поля из раздела 7 AGENTS.md)
- `signal_categories` — M2M (сигнал → несколько ЖС)
- `status_history` — аудит переходов (нужно для напоминаний >3 дней)
- `sources_state` — per-source дата последнего успешного обхода (доверстывание)
- `documents_seen` — дедуп независимо от создания сигнала
- `experts` — whitelist

## 3. Переиспользование `measure_deepagent`

Ревью репозитория сделано, см. `docs/STAGE0.md`, раздел 1. Вывод: переиспользуем
отдельные приёмы (2–3 штуки), не архитектуру и не код 1:1:
- многоступенчатый fallback fetcher'а (прямой запрос → прокси → альтернативный ридер) —
  адаптировать приём под наши источники, не копировать код;
- `apparent_encoding`-приём для доменов без charset в заголовках (`garant.ru`,
  `pravo.gov.ru` отдают cp1251 без объявления) — скопировать;
- PDF→текст через `pypdf`/аналог без OCR — взять как baseline, OCR-fallback дописать
  самим (в `measure_deepagent` отсутствует).

Не переиспользуем: полнотекстовый поиск НПА по названию меры (SearXNG/Yandex Search —
решает другую задачу), сам LLM-харнесс экстрактора карточек (это и есть внешний «агент
автообновления», вне периметра), regex-эвристики под конкретные меры/источники (не
обобщаемы), инфраструктуру eval/скоринга (методика оценки — отдельный контур).

`parser/fetcher.py` пишем заново (httpx+tenacity), как и запланировано ниже.

## 4. Белый список источников MVP и сетевые ограничения

Полная таблица со статусом проверки каждого источника — `docs/STAGE0.md`, разделы 2 и
2.1. Кратко:
- `sfr.gov.ru`, `mintrud.gov.ru`, `mos.ru/authority/documents/`,
  `msupport.dszn.ru` — проверены, доступны напрямую.
- `publication.pravo.gov.ru`, `kremlin.ru`, `government.ru` (сеть RSNET) — не отвечают
  на прямые запросы с не-РФ IP на 443/80; рабочая схема — RU-прокси **по HTTP** (443
  фильтруется даже через RU-прокси, 80 — открыт). Подтвердить актуальность схемы на
  боевом VPS перед продакшен-запуском.
- `dszn.ru`/`mos.ru/dszn/` — контент рендерится через JS, нужен Playwright/аналог или
  внутренний API endpoint вместо голого HTTP GET — не блокирует MVP, пока используется
  `mos.ru/authority/documents/` + `msupport.dszn.ru`.
- `r.jina.ai` как fallback-ридер — исключён из стека (не обходит гео-блокировку RSNET).

## 6. Решения по открытым вопросам

См. AGENTS.md, раздел 16 — статус каждого пункта (🟢/🟡/🔴). Ключевые решения:
- PDF/OCR — fallback-архитектура: текстовый слой основной, OCR (`pytesseract`, ru) —
  только если текст пустой/короткий.
- Дата вступления в силу — regex-эвристики первой итерацией («вступает в силу с…»),
  LLM-разбор вторым проходом, если покрытие низкое по итогам пилота.
- Повторное открытие «Отклонён» — команда `/reopen <id>`, перевод в «Новый» с записью
  в `status_history`.
- Связь с `measure_deepagent` — не жёсткая зависимость, опциональное переиспользование
  fetcher/parser-приёмов как отправной точки (см. раздел 3).

## 7. Чек-лист задач (для ralph-цикла)

Каждая задача выполнима за одну итерацию: код + (где применимо) тесты + коммит.

Правила работы с этим разделом (важно для `ralph.sh`/`RALPH_PROMPT.md`):
- Задачи выполняются **сверху вниз**, по одной за итерацию, в рамках текущей
  незавершённой фазы — фазы не пропускаются и не распараллеливаются.
- Выполненная задача помечается `[x]`. Если задача заблокирована (нет доступа/кредов/
  контракта) — оставить `[ ]` и дописать `<!-- BLOCKED: причина -->` рядом, перейти к
  следующей незаблокированной задаче.
- Любое отклонение от AGENTS.md (найдена неточность, нужно уточнение) — фиксировать в
  разделе «Открытые вопросы» AGENTS.md (раздел 16), не изобретать требования на ходу.
- Каждая завершённая задача — отдельный git-коммит с понятным сообщением.
