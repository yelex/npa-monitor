# npa-monitor

Мониторинг изменений в НПА (нормативно-правовых актах) по мерам поддержки для
ветеранов боевых действий, людей с инвалидностью и участников СВО. Полный контекст
требований и архитектурные решения — [AGENTS.md](AGENTS.md), план и чек-лист по
фазам — [PLAN.md](PLAN.md).

## Структура

- `db/` — модели SQLAlchemy 2.0, слой сервисов (переходы статусов, дедуп), SQLite WAL.
- `parser/` — ежедневный сборщик публикаций (`sources/` — адаптеры под источники).
- `bot/` — Telegram-бот, интерфейс эксперта.
- `data/` — справочники (ЖС, регионы, белый список источников) — данные, не код.
- `docs/` — исходные требования, xlsx-примеры карточек мер, `STAGE0.md`
  (диагностика источников/сети).
- `tests/` — юнит-тесты.

## Разработка

Требуется Python ≥3.10.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

Переменные окружения — скопировать `.env.example` в `.env` и заполнить реальными
значениями (файл `.env` не коммитится, см. `.gitignore`).

```bash
cp .env.example .env
```

### Тесты и линтер

```bash
pytest
ruff check .
```

### Запуск бота

Нужен как минимум `TELEGRAM_BOT_TOKEN` и `ALLOWED_TELEGRAM_USER_IDS` в `.env`.

```bash
python -m bot
```

БД (SQLite) создаётся автоматически по пути `DATABASE_PATH` (по умолчанию
`data/npa_monitor.db`) при первом запуске.

Утренняя сводка (~08:00) и напоминания о сигналах >3 дней в работе рассылаются самим
ботом в фоне, пока он запущен (`_digest_loop`/`_reminder_loop` в `bot/main.py`) —
отдельно ничего планировать не нужно.

### Запуск парсера

Один прогон по всем источникам, не демон — планируется извне (AGENTS.md раздел 14:
ежедневно в 06:00).

```bash
python -m parser
```

Пример строки `crontab -e` (venv в `/opt/npa-monitor/.venv`, проект в
`/opt/npa-monitor`, переменные — в `/opt/npa-monitor/.env`):

```cron
0 6 * * * cd /opt/npa-monitor && .venv/bin/python -m parser >> /var/log/npa-monitor-parser.log 2>&1
```

Эквивалент systemd timer — юнит `npa-monitor-parser.service` (`ExecStart=... -m
parser`) + `npa-monitor-parser.timer` (`OnCalendar=*-*-* 06:00:00`); конкретные unit-
файлы для боевого VPS — Фаза 7 (Деплой), здесь только сам entrypoint.

## Статус

Реализация ведётся по чек-листу в [PLAN.md](PLAN.md), фаза за фазой. На данный момент
готовы Фазы 0–6 (скелет проекта, БД, справочники, парсер источников, классификация,
Telegram-бот, интеграция парсер↔бот + планирование) — см. таблицу этапов в PLAN.md. Не
хватает интеграции с внешним «агентом автообновления» (Фаза 5, заблокировано — см.
AGENTS.md раздел 16 п.8) и Фаз 7–8 (деплой, приёмка).
