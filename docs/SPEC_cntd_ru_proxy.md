# Спека: docs.cntd.ru — unsupported → ru_proxy (автопроверка ссылок ботом)

Статус: **к реализации** (мини-фикс).

## Контекст

`data/sources.yaml`: `docs.cntd.ru` имеет `access: unsupported` по итогам
диагностики Этапа 0 (20.08, таймаут + SSO-redirect-loop). Из-за этого бот
принимает ссылки cntd «на доверии» без автопроверки доступности.

Диагностика 25.08 (после стабилизации RU-прокси, allow-лист включает IP VPS):
- direct: таймаут (000, 15s)
- **через RU-прокси `http://95.142.42.28:8888`: 200 за 0.7 с** (`/document/1314770295`)

В npa-somas фетч cntd через прокси подтверждён боем (E2E sig-106, прогон 77_13):
нормализация URL (срез `?marker=` у cntd) + прокси-фолбэк + charset-decode.

## Решение

- `data/sources.yaml`: `docs.cntd.ru` → `access: ru_proxy`, обновить note
  (проверено 2026-08-25, прямой — таймаут, через прокси — 200).
- Бот начнёт прогонять `fetch()` с `ru_proxy_url` для cntd-ссылок (код уже
  умеет ветку `ru_proxy`, ничего менять не надо — только данные).
- Ограничение: SSO-redirect-loop на части страниц (comments) не лечится —
  если фетч вернёт SourceUnavailable, аналитик получит обычное «ссылка
  недоступна» и сможет продолжить (skip/файл) — это корректная деградация.

## Проверка

- Юнит: `access_for_domain('docs.cntd.ru') == 'ru_proxy'`, домен остаётся в
  белом списке (существующий тест справочника обновить).
- Ручной: ссылка `https://docs.cntd.ru/document/1314770295` в флоу бота —
  принимается без «проверьте вручную».

## НЕ входит

- Обход SSO-loop для страниц cntd с авторизацией.
- Изменение фетчера бота (он уже поддерживает прокси).
