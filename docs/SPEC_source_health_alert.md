# SPEC: Алерт о деградации источников парсера

## Статус
Implemented (02.09.2026), не задеплоено — ждёт ревью.

## Контекст
Инцидент 02.09: RU-прокси лежал ~4 дня, Yandex-ключи потеряны из .env — парсер
писал только WARNING в лог cron, 0 сигналов 4 дня подряд. Эксперт в TG увидел
деградацию только глазами («мало новостей»). Бот уже умеет слать сообщения
allowed-пользователям (`send_digest`, aiogram).

## Проблема
Нет канала доставки информации о здоровье источников до эксперта. Парсер —
одноразовый контейнер (cron), сам слать не может и не должен.

## Предполагаемый фикс
Парсер в конце прогона пишет в БД (или возвращает в stdout-итог) сводку
здоровья: сколько источников ok/failed по `sources_state`. Если:
- ≥2 источников failed, **или**
- прогон дал 0 новых сигналов при 0 ok-источниках среди ЖС-значимых
  (pravo.gov.ru, yandex_search, kremlin, government),
то после прогона бот должен отправить allowed-пользователям алерт-сообщение:
какие источники упали, когда последний успешный обход, подсказка
(«проверь прокси/ключи»).

Реализация (минимальная, без новой очереди):
1. Парсер `__main__.py` в конце пишет health-итог в stdout последней строкой
   JSON-маркером (как现有 лог) ИЛИ — предпочтительно — в `sources_state`
   уже есть `last_success_at`/`last_attempt_at` — алерт-чекер ходит по ним.
2. Новый модуль `bot/health_alerts.py`: функция `check_source_health(db)` →
   список источников, у которых `last_attempt_at` значительно свежее
   `last_success_at` (≥2 подряд неудачных попыток за 24ч). Вызывается из
   `_digest_loop` перед отправкой digest: если есть больные — первой
   сообщением отправить ⚠️ сводку.
3. Тесты: источник с 3 попытками без успеха → алерт; все успешные → тишина;
   дедуп алерта (не спамить каждый digest — статус в БД или отдельный файл
   state, TTL 24ч).

## Как воспроизвести
- Остановить tinyproxy, запустить парсер 3 раза → на следующем digest
  бот должен прислать ⚠️ «publication.pravo.gov.ru: недоступен с ...».
