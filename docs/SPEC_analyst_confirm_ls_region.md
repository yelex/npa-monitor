# SPEC: Подтверждение ЖС и региона аналитиком при передаче агенту

## Статус
Agreed (дизайн согласован с Claude 2026-08-24, см. раздел «Решения»).

## Контекст
Флоу бота: сигнал → «✅ Взять в работу» → FSM `NpaFlow.ask_npa_link` (ссылка на НПА или skip) → статус `SENT_TO_AGENT` + `_autoupdate_client.send(...)`.

ЖС (`SignalCategory`: veterans/disabled/svo, M2M `signal_categories`) и регион (`Region`: rf/moscow/undefined) уже заполняются парсером/классификатором автоматически, но аналитик их не видит и не может скорректировать перед передачей агенту автообновления. Классификатор иногда ошибается (Фаза 9 п.6 — аудит ложных срабатываний), а решение об ошибке принимает аналитик в момент взятия в работу.

## Проблема
Агент автообновления получает ЖС/регион из классификатора без человеческого подтверждения. Ошибка классификации тиражируется дальше по конвейеру.

## Решения (по итогам обсуждения с Claude, 2026-08-24)
1. **Порядок:** ссылка → ЖС → регион → `SENT_TO_AGENT`+send. Терминальная логика (transition+send) выполняется один раз после выбора региона; skip-путь проходит те же шаги без развилок в коде.
2. **ЖС:** toggle-кнопки ✅/⬜ + «Подтвердить» (паттерн как `priority_filter_kb`). Callback `catc:<sig>:<code>` / `catc:<sig>:confirm`. Текущий выбор в `state.update_data(categories=...)`, БД трогается один раз в финальном коммите. Пустой набор блокируется alert'ом.
3. **Регион:** кнопки (РФ/Москва/Не определён) + «Другое» → free text → поиск по `db/catalog.load_regions()` (casefold, подстрока по name/code): 1 матч → принять, 0 → «не найден», 2+ → уточнение списком. Новый Region на лету не создаём; переживает расширение справочника до 89 субъектов.
4. **Payload агенту:** сигнатуру `AutoUpdateAgentClient.send()` не менять (контракт ещё не выбран, AGENTS.md п.16.8); источник истины — `Signal` в БД, реальный клиент прочитает сам.
5. **Аудит коррекций:** подтверждённые значения перезаписывают `signal_categories`/`Signal.region`; расхождение с классификатором пишется в `StatusHistory.reason` при переходе в `SENT_TO_AGENT` в grep-able формате `classifier=svo region=moscow -> confirmed=veterans region=rf`. Без расхождения запись не пишем. Без миграции схемы.
6. **FSM:** `NpaFlow` + состояния `ask_categories`, `ask_region`; новые хендлеры `on_category_toggle` (callback `catc:`), `on_region_button` (callback `reg:`), `on_region_manual` (текст в состоянии «Другое»); хвост `on_npa_link` (DB-коммит + transition + send) переносится в финальный шаг после выбора региона. Весь диф локализован в `bot/main.py`, без правок схемы БД.

## Как воспроизвести (текущее поведение)
1. `/signals` → «✅ Взять в работу»
2. Бот: «Отправьте ссылку на НПА»
3. Отправить ссылку → сразу `SENT_TO_AGENT`, ЖС/регион не подтверждаются.
