# Спека: отсечение обзоров/агрегаторов + отмена напоминаний о «зависших» сигналах

Статус: **решение Алексея 2026-08-28, к реализации**.

## 1. Не слать ссылки на обзоры и агрегаторы НПА

**Правило:** обзоры и агрегаторские материалы не содержат конкретики по отдельной
новости → сигналы по ним аналитику не отправлять.

- `EventType.REVIEW` (значение по умолчанию классификатора, `parser/classifier.py::
  detect_event_type`) — сигнал не создаётся (или отбрасывается на этапе создания
  сигнала в парсере), логируется как отфильтрованный.
- Ссылки на агрегаторы (группа `other`, `parser/sources/other.py`: garant/
  consultant/tass/ria/rg) типично и дают REVIEW; фильтр по event_type покрывает
  их автоматически. Отдельного блэклиста доменов не вводим — если конкретика
  (маркер события) в публикации есть, она имеет право на сигнал.
- Точка фильтра: там, где публикация превращается в сигнал (оркестратор),
  НЕ в боте — чтобы обзоры не копились в БД как NEW.

## 2. Убрать напоминание «сигнал в работе >3 дней» (раз в 6 часов)

- Удалить `bot/main.py::remind_stale` + `_reminder_loop` и их запуск в `main()`.
- Обновить упоминания в AGENTS.md (раздел 12) и PLAN.md.

## Проверка

- Тест: публикация REVIEW-типа → сигнала нет; публикация с маркером события →
  сигнал есть. Тест на отсутствие remind-луна (или просто удаление покрытых
  тестов remind_stale).
