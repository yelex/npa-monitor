## 1. Ревью `measure_deepagent`: что переиспользуем

### Резюме

Репозиторий целиком заточен под другой контур — **экстракцию и верификацию карточек мер**
(аналог «агента автообновления» из `AGENTS.md`, п.1), а не под мониторинг публикаций НПА.
Прямого аналога нашего «обходчик источников → детектор новизны → сигнал» там нет: весь код
либо начинается с уже известного `npaUrl` меры (эталонного реестра), либо ищет НПА по
названию меры (поиск), а не наблюдает за источником на предмет новых публикаций.

Зависимостей `requirements.txt`/`pyproject.toml` в репозитории нет — используемые пакеты
(`requests`, `pypdf`, `langchain_openai`, `deepagents`, `langchain_core`) собраны вручную по
импортам, фиксировать для себя нужно заново.

**Вывод: переиспользуем отдельные приёмы (2-3 штуки), не архитектуру и не код 1:1.**
`parser/fetcher.py` пишем заново, как и запланировано в `PLAN.md` (httpx+tenacity).

## 2.1 Диагностика сети (2026-08-19, 22:00–22:25) — РЕШЕНО

**Контекст:** основной VPS `151.243.180.35` — Frankfurt (HOSTKEY B.V., DE), не РФ.
Федеральная тройка (`publication.pravo.gov.ru`, `kremlin.ru`, `government.ru`) — сеть
RSNET (ФСО) — режет иностранные IP: direct curl из DE — TCP timeout по 443 и 80.

**Схема r.jina.ai (рекомендованная как первый кандидат) — НЕ работает:**
- jina отдаёт `422 TimeoutError` — их headless-браузер грузит страницы из не-РФ
  датацентров и упирается в ту же гео-блокировку. Выбрасываем из архитектуры.

**RU-прокси `95.142.42.28:8888` (tinyproxy на сервере yellex.com, EuroByte, RU) — работает, но с нюансами:**

Диагноз «прокси мёртв» был составным:
1. **443 до RSNET-доменов фильтруется даже с RU-сервера** (TCP connect timeout,
   DNS при этом чистый — те же IP через 8.8.8.8/1.1.1.1; ya.ru/google.com с RU-сервера
   работают). Именно поэтому HTTPS через прокси таймаутил — прокси тут ни при чём.
2. **Порт 80 до RSNET — открыт.** HTTP через прокси работает идеально:
   - `http://publication.pravo.gov.ru/` → 200, 28 КБ
   - `http://www.kremlin.ru/acts/news` → 200, 47.6 КБ (~1.5 c из DE через прокси)
3. Юнит systemd был в `failed(timeout)` из-за кривого `Type=forking` без валидного
   PIDFile + осиротевший процесс после ребута сервера. Исправлено drop-in
   `/etc/systemd/system/tinyproxy.service.d/override.conf` (`Type=simple`,
   `ExecStart=/usr/bin/tinyproxy -d`), orphan-процессы убиты, сервис перезапущен —
   `active`, порт 8888 слушает, сквозная проверка DE→proxy→pravo/kremlin проходит.

Allow-фильтр tinyproxy: 127.0.0.1, 46.30.43.146, 91.217.194.19, **151.243.180.35** (наш VPS — уже прописан).

**Итоговая схема fetcher (уточнение раздела 3):**
- `sfr.gov.ru`, `mintrud.gov.ru`, `mos.ru` — direct HTTPS из DE
- `publication.pravo.gov.ru`, `kremlin.ru`, `government.ru` — через
  `http://95.142.42.28:8888` **по HTTP** (scheme=http в URL; 443 фильтруется — не пытаться)
- `r.jina.ai` — исключён из стека
- Контент публичных НПА-публикаций по HTTP без TLS — приемлемо для MVP (данные открытые)
- r.jina.ai из measure_deepagent не даёт обхода гео-блока — см. выше

## 3. Что это значит для Этапа 2 (parser)

- `parser/sources/` пишем с нуля под 5 подтверждённых листингов (`sfr.gov.ru` × 2 раздела,
  `mintrud.gov.ru` × 2 раздела, `mos.ru/authority/documents/`) + 3 источника, структуру
  которых нужно снять первым делом с рабочего VPS (`pravo.gov.ru`, `kremlin.ru`,
  `government.ru`), поскольку без них MVP по ветеранам/инвалидам/СВО не покрывает
  федеральный уровень, как того требует `AGENTS.md` раздел 4.
- `parser/fetcher.py`: httpx+tenacity (уже решено в `PLAN.md`) + `apparent_encoding`-подобная
  автоопределение кодировки под gov-домены без charset в заголовках (приём из
  `npa_fetcher.py`, см. таблицу выше).
- PDF: pypdf как основной слой (тексто-слойные PDF), pytesseract-fallback — писать самим,
  готового кода под него в measure_deepagent нет.
- Для `mos.ru/dszn/` (и любых других JS-рендер-разделов) — заложить в оценку Этапа 2, нужен
  ли Playwright/аналог в стек парсера, или достаточно обходиться без этого раздела и опираться
  на `mos.ru/authority/documents/` + `msupport.dszn.ru` (оба статические/API-доступные).
